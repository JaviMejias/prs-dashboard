# Reglas de revisión

- Respeta la compatibilidad del runtime y de las dependencias existentes antes de proponer APIs nuevas.
- Revisa primero cambios de autorización, datos, callbacks, transacciones y efectos secundarios.
- En código legado, busca regresiones en consumidores relacionados y no evalúes un archivo de forma aislada.
- Comprueba que los cambios mantengan el estilo y las convenciones del repositorio.
- Distingue problemas bloqueantes, riesgos de regresión y observaciones menores.
